## 0. 中心诊断:阶梯没有失效,是我的证书公式记错账

实测"zoom≥120 时 100% 像素落 DD"曾被解读为"阶梯在深处失效"。审计 + 复盘证明这是**记账错误**:

`CertifiedIterator` 第 106 行把表窄化误差 `ulp_table·|Z|` 塞进了复利递推
`e ← |f'|·e + …`,即按"动力学扰动"记账,随 λⁿ 复利。**它不是动力学扰动**:

- delta 递推跑在**真轨道的窄化导数表**上,表的相对噪声对 d 是每步 `+ulp`(相对),不复利;
- 重构 `z = Z_stored + d` 时的表误差 ε_n ≤ ulp_table·|Z| 是**读数误差**——每步独立出现在
  输出端,不进入下一步的动力学。
- 于是我的公式对 n 步像素多收 λⁿ 倍罚金:FP64 在 n=117 时被收 10²⁴ 倍 ⇒ 必然弃档;
  DD 勉强通过纯属侥幸(1e-31·10²⁴ ≈ 1e-7 恰好低于判定裕度)。

**修正记账后,深处的快逃逸+全程耦合像素理应在 FF32/FP64 档退休**——阶梯的核心假设
(多数像素便宜档)在深处依然成立,先前的实测否定作废,须修复后重测。

这同时化解了审计的"自相矛盾"指控(§B2/§B31):"D* 平坦"推导与逐步复利表项不可同真——
错的是后者。

## 1. 三本账证书(替换现行单标量递推)

**原则:无免费近似。任何路径上的任何近似,必须向账本付费;付不起,换路径或升档。**

### 账本 A:动力学相对账 `e_rel`(无量纲,随 d 演化)
d 的相对误差。更新规则:

- **耦合步**(泰勒路径):`e_rel += c_arith·ulp_rung + c_table·ulp_table + C_trunc·u²`
  - `c_arith·ulp`:d 算术噪声(相对,放大与 δ 增长同步抵消,见 v1 §2.2——该定理本身没错);
  - `c_table·ulp_table`:导数表相对噪声;
  - `C_trunc·u²`:**二阶泰勒截断的显式付费**(修 BLOCKER"证书缺截断项")。
    `C_trunc = |f'''·Z²/(6f')| = |(p−1)(p−2)|/6 ≈ 2.3`(本映射),u = |d_true/Z|。
    注:现行阈值 u < ulp^(1/3) 下截断项累计可达 1e-18,**远超 DD 的 ulp**——
    以前是静默损失,现在是显式付费,证书自然吸收。
- **解耦步**(精确路径):`e_rel ← e_rel · A_n + c·ulp`,其中
  **`A_n = |f'(z_n)|·|d_n|/|d_{n+1}|` 用当步实测值**,不用全局 λ。
  这修掉"0.204 是时间平均不是上界"(BLOCKER §B34):证书里**从此没有 λ**;
  极点邻近的单步 16.8 位会被当步实测 |f'| 如实记账,像素自然升档。
- **重锚步**:`e_rel += 2·ulp_table·|Z| / |d_new|`(两个表项的绝对误差折进新 d;修锚点注入)。

### 账本 B:显示账(每次读数临时合成,不复利)
任何决策点(逃逸判定/陷阱取值/最终着色)的点误差:
`e_display = e_rel·|d_true| + ulp_table·|Z_n|`。
表项**只在这里出现**。这就是 §0 修复的落点。

### 账本 C:决策接受 → 区间算术(替换 Lipschitz 机制)
接受测试全部改为**区间求值**:输入球 `z ± e_display`,陷阱函数/平滑迭代数/ColorBand
逐操作区间传播(double 端点,每操作加 1 ulp 外扩)。一次性修掉四条 BLOCKER:

- "陷阱最小值聚合错误"(§B40):运行 min 直接以区间形式维护 `[min(lo), min(hi)]`;
- "敏感度取算点而非上确界"(§B43):区间就是上确界;
- "0.75 幂在 base→0 导数无界"(§B49):区间在该处自然放宽 ⇒ 像素升档,行为正确;
- 钳位区不可导:区间算术不需要导数。

**分支切割判定入账**(§B46):若 `|θ ± π| < e_θ`(θ 的区间半径),分支选择不可证 ⇒ 升档。

### 溢出/下溢卫生(§B55)
主账本是**相对**账 e_rel(无量纲),不随 d_true 下溢归零;重构 offset 下溢 double 时
其对 z 的贡献 < 1e-308,如实记 0 是正确的。renorm 补**双向**:leading < 1e-15 也要上调
(现行只处理过大)。

## 2. 重锚降级,AP 兜底,黑洞像素归零

- **重锚(D3)降级为优化**,不再是架构支柱。审计正确:重锚不能恢复泰勒路径
  (锚距 ~1e-2 ≫ 阈值),也不能消除已注入误差。它仍保留——缩短 |d| 使未来注入变小、
  改善精确路径条件数——但**长游走像素的真正机制是升档**,预算由账本 A 如实给出:
  每档可承受解耦步数 ≈ 位数/0.204(FP32≈30 / FF32≈65 / FP64≈75 / DD≈150 / QD≈300)。
- **新增 AP 兜底档(rung 5,CPU)**:任意精度直接迭代,精度自适应
  (P 与 P+20 各算一遍,窄化结果一致才接受,不一致加宽重算)。
  ⇒ **"未认证像素不写缓冲"的黑洞(§B5)从此不存在:每个像素必然在某档终结。**
- 轨道烘 **2·N_max** 长度(修重锚越界 §B17),越界残余走 AP 档,永不判黑。
- 烘焙自身加 a-posteriori 验证:P 与 P+20 两遍,窄化表逐项一致才交付
  (λ 只用于初值估计,正确性不依赖它)。

## 3. 阶梯顺序按后端定策(关键新认知)

**CPU 上 float 和 double 同速**(标量与 SIMD 宽度差 2×),FF32(~14位)对 CPU 毫无意义
——同精度下 FP64 更快。**FF32 的存在意义是 GPU**:消费卡 FP32:FP64 = 32~64:1。

| 后端 | 阶梯顺序 | 理由 |
|---|---|---|
| CPU | FP32(SIMD×8) → FP64(SIMD×4) → DD → QD → AP | float/double 硬件同速,跳过 FF32 |
| GPU | FP32 → FF32 → FP64 → DD;QD/AP 回 CPU | FF32 跑 FP32 单元,是消费卡主力档 |

`RungIndex` 从常量改为**后端策略表**。

## 5. CPU 拉满

1. **修证书 → 重测阶梯分布**(预期深处快逃逸像素落回 FP64 甚至 FP32,这是最大单笔收益:
   DD→FP64 约 5-8×,若成立深帧再提一个量级);
2. **自适应泰勒路径**:凭 `C_trunc·u²` 付费扩大泰勒适用域(u 上限从 1e-10 级放宽到
   账本允许的程度),精确路径(每步 8+ 次超越函数)从常态变为罕见 ⇒ 解耦段成本大降;
3. **SoA + 迭代分块 + 车道压缩 + `Vector<T>`**:像素状态列存,64 步一块,活跃像素压缩,
   耦合路径 8 宽 float / 4 宽 double 向量化;发散(逃逸/升档/精确路径)像素落队列标量处理。
   这个形状与 GPU 内核同构——CPU SIMD 版就是 GPU 移植的排练;
4. 预算参考(24T,1080p,N=300):当前标量 DD ≈ 3.6 s/帧 → 修账+自适应泰勒+SIMD
   目标 **0.5-1.5 s/帧**(门禁实测定案,不作承诺)。

## 6. GPU 拉满

- **前提:证书数学定案并在 CPU 通过全部门禁之后**(v1 的裁决不变,现在地基修好了才能动);
- ILGPU,per-rung kernel(FP32/FF32 吃 FP32 单元;FP64/DD 吃 FP64 单元),三本账全部
  进内核(全是 double/float 标量,无障碍);QD/AP 留 CPU;
- 门禁:逐 rung 与 CPU oracle 证书级一致(颜色逐像素相等,采样≥1e4);
- 预算参考(4090 级,1080p):FF32 主导帧 **30-150 ms/帧**;DD 主导帧 2-4× CPU。
  全片 5161 帧:GPU **数分钟到半小时**量级。同样门禁定案。

# V2.1 修正案(对抗审计裁决后的强制修订,2026-07-28)

三个独立攻击面(账本数学 / 区间与升档 / 性能与覆盖)的裁决:sound-with-corrections / unsound /
sound-with-corrections。**§0 中心论点在三路攻击下全部存活**——最承重的一条(解耦路径表误差是否相对)
被显式推导确认:`Δd' = −f'(z_n)·d·(ε/Z)`,表误差恰以账本自己的 A_n 弹性进入,**深处认证不塌**。
以下修正全部强制,实施时公式以本节为准,§1 原文视为已被覆盖。

## 账本 A(修订版更新规则)

- **解耦步**(修 3 处):`e_rel ← (e_rel + c_table·ulp_table + c_u·ulp_rung) · A_n + c·ulp`
  - 新注入必须乘 A_n(平坦 +c·ulp 不是上界;首步极点邻近最多欠收 350×);
  - **A_n 的 |f'| 取误差球上确界**:`|p|·(|z_n| − e_abs)^(p−1)`,且 `e_abs ≥ |z_n|/2 时立即升档`。
    三个审计 agent 独立命中同一处——B43 缺陷在账本 A 内复活,区间层(账本 C)够不到它;
  - 分母用 `|d̂_{n+1}| − e_abs'` 或等价补偿;`|d_{n+1}|→0` 除零卫。
- **重锚步**(BLOCKER 修复):`e_rel ← e_rel·(|d_old|/|d_new|) + (2·ulp_table + c_sub·ulp_rung)·|Z|/|d_new|`
  ——旧公式漏掉首项重标定,按 0.5 增益门每次至少欠收 2×,高增益重锚无界欠收。
- **耦合步**:`C_trunc = 2.3/(1 − 1.31·u_max)`(几何尾),更新乘 `(1 + 5u)`(耦合传播因子),
  u 取球上确界 `(|d|+e_abs)/|Z|`;二次项舍弃门本身再收一个 ulp ⇒ `c_arith = 2`。
- **全局帽**:`e_rel > E_max = 0.1 即升档`;所有实测量乘 `1/(1−E_max)` 封闭二阶循环依赖。

## 账本 B(修订版)

`e_display = e_rel·|d̂|·(1+E_max) + ulp_table·|Z| + c_add·ulp_rung·|z| + 1.11e-16·|z|`
最后一项(rung→double 窄化)在 DD 档比原表项大 **15 个数量级**、QD 档大 45 个——原公式的最大单洞。

## 账本 C(修订版)

- 球种子必须含账本 B 全部项(尤其 double 窄化项);端点外扩用 `BitDecrement/BitIncrement`,
  禁止乘 (1±ε)(在 0 和次正规数处失效)。
- **超越函数逐函数外扩常数**(实测+余量,≥4 ulp;.NET 无舍入界担保,本仓已实测 Fp64 ExpM1 1.31 ulp、
  FF32 LogP1 7.08 ulp);1 ulp 只许用于 +−×÷√。
- **区间 cos 必须检测跨 π 整倍数并纳入极值**——否则整数 t 带(每帧可见的暗色带曲线)会被端点法
  认证成错误字节(u=0.01 时认证蓝=1、真值=0,区域级伪影)。§4 的 B49 行更正:base→0 处区间
  **认证黑字节**而非"放宽升档"。
- 逃逸不确定度补 `+e²`(精确式 `(|z|+e)²−|z|²`);逐步裕度测试保留——它就是钉住逃逸整数的结构。
- 分支切割 `e_θ = c·ulp_rung + ulp_table + e_rel·|u|/|1+u|`(显式播种)。

## 升档与 AP(修订版)

- **AP 从投票档改为认证档**:携带逐操作误差递推(球算术),分支/量化裕度测试照做;
  P vs P+20 一致性降级为交叉检查——一致可以同错,且阶梯恰好把贴边像素灌进 AP。
  烘焙验证同改。终结规则:P_max 仍贴边 ⇒ 记录容差、判定"边界歧义像素"并定侧——终止成为定理。
- **I6 NaN 语义 × 区间**:黑改为**认证决策**——`sign(smoothIters)` 区间 hi<0 ⇒ 认证黑(不算 log2),
  跨 0 ⇒ 升档,lo>0 ⇒ 继续。NaN 端点永不进比较,否则浅帧 |z₀|<0.045 的整块黑盘在 AP 无限重算。

## 常数与性能修正

- **FF32.RelativeUlp = 3e-14**(我 §4 写的 2e-14 低于实测 2.52e-14——修复表里复活了被审计的缺陷)。
- 常数全部落数字并由 P0 门禁断言与文档一致:`c_arith=2(耦合)`、`c_table=1`、按路径给出解耦计数。
- **GPU**:账本+区间接受必须 float/FF32 驻留——否则 FP64 单元瓶颈一切档位;FF32 对 FP64 的诚实
  每操作优势 **~5-6×**(非 32-64×;每 FF32 操作 ≈ 8-20 条 FP32 指令)。30-150ms/帧目标经算术复核仍成立。
- **CPU**:每步 ≥80% 是档无关的 double 记账 ⇒ FP32(SIMD×8) 对 FP64(SIMD×4) 实际收益 ~1.1-1.2×;
  深帧必须有**入档预测器**(按上帧同 tile 认证直方图起跳),否则 FP32 空跑等于帧时翻倍。
  0.5-1.5s/帧目标仍成立(FP64-SIMD 理想 ~0.2s,余 3-7× 余量)。
- **P3 前置微基准**(不过不动 GPU):CUDA 后端断言 `fma(a,b,−a·b) ≠ 0` 并 grep PTX `fma.rn`
  ——软 fma/mul+add 会让 EFT 残差恒 0,FF32/DD 静默退化成 FP32/FP64 而证书照旧;FTZ/fast-math 必须关;
  IPrecision 的 static abstract / stackalloc 需确认 ILGPU 前端支持,预期要做内核方言移植。
- **区间库是未建的承重件**,列为 P0 具名门禁(操作集+逐操作外扩常数+实测 harness)。
- 网格统一后 **0.343 门禁必须重定基线**(P2),否则承重回归门静默死亡。
- 措辞更正:"每帧成本与 zoom 弱相关" → **"与深度线性(N 内容驱动),出货区间内平坦"**;
  烘焙加断言 `D* ≥ zoom·0.30103 + log10(横向像素数) + guard`,隐式耦合不许再靠运气。
