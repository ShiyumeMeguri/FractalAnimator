## 1. 问题与实测事实(全部来自本仓库实测,可复现)

**目标**: `腐化监视` = Julia 集 z ← z^p + K,p = −2.23(非整数负幂),K = (−0.77781, −0.23656)×1e-5
(注意:一切常量取 **double 的精确二进制值**,见 §6 不变量 I2),FractalParadise B-style 轨道陷阱着色,
无限深缩放视频,单中心,zoom(log2)可到 340+(10^100 ⇒ zoom≈332)。

关键实测(720²、zoom 120、N=300,`--deepglitchrate`/`--pixeltruth`/`--glitchthresholdsweep`):

- 该映射逐步误差放大率(Lyapunov)**λ ≈ 1.6×/步 = 0.204 十进制位/步**(`--deeppixeltrace` 逐迭代对拍测得)。
- 旧架构(double 微扰 + 1e-6 Pauldelbrot + tile repair):217.6 s/帧,其中 repair 215 s(98.8%),
  像素循环仅 0.557 s(0.26%),需 662 条修复轨道。**且已被任意精度仲裁证明有错**:8 个争议像素 0/8 正确。
- dd 微扰 + 仅抵消判据:26.0 s/帧、0 修复,但 ~0.04% 像素错(仲裁:修复版 6/8 更近真值)。
- dd + 误差预算(100 步)+ repair:**8/8 与任意精度真值完全一致**,但 flag 6.8% 像素 ⇒ 4507 条修复轨道
  ⇒ 3489.5 s/帧。当前代码停在此(正确但慢)。
- 单条 300 迭代 AP 轨道(~135 位)构建 ≈ 2.7 s;dd 像素循环 720²×300 ≈ 22.5 s(CPU 并行)。
- 三个历史 bug 指纹(留作回归测试,§6):
  (a) 循环边界 off-by-one ⇒ 每像素同差一个常数(`maxAbsDiff == meanAbsDiff` 是指纹);
  (b) `FromDouble` 走 "R" 十进制字面量 vs 二进制精确值差 1e-17 ⇒ 高精度对拍永远"差 1e-17";
  (c) 保真门基线:`--deepcorruptioncompare 40 300 40` ⇒ meanAbsRgbDiff = **0.343**(8-bit 取整噪声,不许恶化)。

## 2. 误差动力学:四条定理(整个架构的数学地基)

### 2.1 误差递推是表象无关的
任何有限精度方法追踪像素轨道 z_n,其绝对误差满足
`e_{n+1} = |f'(z_n)|·e_n + (本步注入)`。沿混沌轨道 ∏|f'| ~ λ^n。这与用什么表示(直接迭代/微扰/rebase)无关。
**方法之间唯一的差别是"本步注入"的大小。**

### 2.2 微扰的真正价值(为什么它是精度技巧而非速度技巧)
δ 的方程只含 δ 和固定表格 Z_n,z 的误差不回馈进 δ。**耦合(线性)阶段**注入 = ulp·|δ_n|,
之后被放大 |δ_末|/|δ_n| ⇒ 每步贡献 ulp·|δ_末|。300 步总误差 ≈ 300·ulp·|δ_末| —— 与 λ 无关!
**解耦阶段**(|δ| 饱和到 O(1)):注入 ulp·O(1),之后按 λ^剩余步 放大 ⇒ 每个解耦步烧掉 0.204 位。
这就是实测"预算"现象的严格解释:精度 P 位 ⇒ 最多承受 `P/0.204` 个解耦步。
FP32≈30 步,FF32≈65,DD≈150,QD≈305。

### 2.3 迭代精度与 zoom 无关(D1 的证明)+ 取景校正
轨道计算只需把"沿途注入×放大"压到容差下:`ulp·λ^N ≤ tol` ⇒ 需 `0.204·N + 若干` 位,**与 zoom 无关**。
zoom 只出现在两处:(i) 像素偏移 δ_c 的数量级——已由现行"重标定 δ + 整数指数"表示解决;
(ii) **取景**:中心坐标必须精确到 zoom+3 位,否则画面平移。解法:轨道从"舍入到 D* 位的中心"起算,
把**精确的舍入余量**(AP 相减,一次/视频)加进每个像素的 δ_c——余量本身用重标定表示,无损。
于是:`D* = (最细定长档位数 63[QD]) + 0.204·N + 12 守卫`,N=400 ⇒ **157 位,永远平坦**。
(为什么加 63:QD 档要求轨道表在第 n 步的误差 ≤ QD ulp,即 1e-D*·λ^n ≤ 1e-63。)
**推论:10^100 和 10^1000 的每帧成本相同。** 旧的"成本随深度爆炸"曲线整条消失。

### 2.4 逐像素误差证书(D2,取代一切启发式)
每像素带一条 double 标量 `e`(z_n 的绝对误差上界):
```
e ← |f'(z_n)|·e + ulp_档位·|δ_{n+1}|·2^s + ulp_轨道表·|Z_{n+1}|
```
|f'|:耦合时查表 |f'(Z_n)|,解耦时 |p|·|z|^(p−1)(反正精确步里已算出所需量)。rebase 是重表达,
只加一次减法 ulp。**接受判据**:每个决策点的裕度 > e——
(i) 逃逸判定:`| |z|² − 1024 | > 2e·|z|`;(ii) trap 最小值:候选 min 之间的差 > L·e(L = trap 的
Lipschitz 常数,由其解析式给出,含 1e-10 clamp 的保守界,预计算);(iii) 最终颜色对 (trapMin, smoothIter)
的导数 × 误差 < 半个 8-bit 量化步。任何一条不满足 ⇒ **该像素升一档重算**(不是"修复",是升精度)。
这把整个渲染器变成**认证精确**:每个输出像素都携带"与无穷精度结果一致(至量化)"的证明。
比现状更强,也比我所知任何现有分形渲染器都强。

## 3. 架构

### 3.1 每视频一条主轨道
中心固定 ⇒ 整条视频共享一条 AP 轨道(D* 位,长度 **2·N_max**,理由见 §3.2 末),连同表格:
`Z_n`、`f'(Z_n)`、`f''(Z_n)/2`、`Z_n^p`、`|Z_n|²`、`trap(Z_n)`,分别窄化为 FP32/FF32/DD/QD 四套数组。
全部表 < 100 KB ⇒ 常驻 GPU L1/constant。构建成本秒级,一次性。

### 3.2 Zhuoran rebasing(D3):零修复轨道
解耦(|δ| ~ |Z|)时,查"最近参考点 LUT"(128×128 网格覆盖吸引子外包框,每格预存最近 Z_m 索引;
一次性预计算):若 `dist(z_n, Z_m) < 0.5·|δ|`,则 `δ ← z_n − Z_m`(dd/qd 中做,无抵消问题),
参考索引跳到 m,继续。这最大化耦合时间、把解耦步数从"轨迹剩余全程"压到"两次接近之间"(~几十步),
**且不建任何新轨道**。本映射的动力学保证了 recurrent 接近:|z|>32 ⇒ 下一步 |z^p| 极小 ⇒ 再下一步 ≈ K,
而主轨道自身也反复途经 K 邻域 ⇒ 天然的 rebase 汇合点。
参考索引 m + 剩余迭代可能越过 N ⇒ 轨道长度取 2·N_max,并在近似并列的候选中优先取小索引。
**tile repair、GlitchFactor、MaxRebasePasses、NthGlitch 及相关代码全部删除。**

### 3.3 精度阶梯(D4):证书驱动的逐像素最小精度
```
rung0 FP32(7 位, 预算~30 解耦步)→ rung1 FF32/float-float(14 位, ~65)
→ rung2 DD(32 位, ~150)→ rung3 QD(63 位, ~305)→ rung4 AP 直接迭代(CPU, 任意)
```
调度:先全图跑低档,证书失败的像素进队列升档重跑(从头重跑该像素——状态小,重跑比保存/恢复便宜)。
**每一档都是完整的引擎**(rebase + 证书 + 精确差分步),不同的只有算术类型 ⇒ 用泛型/代码生成一份逻辑。
- FF32:两个 float 的 Dekker 对,跑在 GPU 的 **FP32 单元上(消费卡 82 TFLOPS 而非 1.3)**——
  这是消费级 GPU 真正的解锁点:大多数像素(快逃逸的外部)在 rung0/1 就能拿到证书。
- QD:按 Bailey 四双精度(renorm)移植 `DoubleDouble.cs` 的全套(含 Log/Exp/LogP1/ExpM1/SinCos/Atan2),
  同样用 `--ddcheck` 模式对 90 位 BigDecimal 验证(容差 1e-58)后才准接入。
- rung4 AP:按证书赤字选精度(通常 <85 位)。**测量点**:若 rung4 人口 > 100 像素/帧,加 rung3.5
  (八倍精度)——预计 rebasing 后 rung4 接近空,先不实现。
- 预估人口(须实测校准):rung0/1 ≈ 75–90%,DD ≈ 10–20%,QD ≈ 1–5%,AP ≈ 0.001%。
- 浅层帧自然落在 rung0 ⇒ **删除 ShallowDeepThreshold 双引擎分裂**,单引擎覆盖 zoom −2 → ∞。

### 3.4 单步公式(维持现行已验证的两条路径,全档位同构)
- 耦合(|u|=|δ/Z| < 1e-8):`δ' = f'(Z)·δ + [½f''(Z)·δ²·2^s](量级门控)`——1–2 次复数乘。
- 解耦:精确差分 `δ' = Z^p · expm1(p·(log1p 差))`,含主值分支跨越检测(照抄现行 dd 实现,
  该实现已通过 8/8 任意精度仲裁)。rebase 优先于精确步:能重锚就不走贵路径。

### 3.5 Phase 3:BLA 跳步 + 区间证书(D6)
标准 Zhuoran BLA:从轨道表预合成跨度 1,2,4,8,… 的线性映射 `δ_{n+m} = A_{n,m}·δ_n`,各带有效半径
(由 |f''| 表严格合成)。**本项目的特殊障碍**:着色是逐迭代 trap-min 和首次越 32 判定,跳过的步也参与。
解法:随 BLA 表预计算两张段表(线段树)——`min_span(trap(Z_n))` 与 `max_span(|Z_n|)`;
跳跃仅当 (a) `min_span − L·R_span > 当前像素 trapMin + L·e`(跳段不可能刷新 min)且
(b) `max_span + R_span < 32 − 裕度`(跳段不可能发生逃逸)。两条都是严格区间论证,精确性不破。
预计对快逃逸/外部像素再省 5–20×。**放在两阶段可用之后做,不阻塞主线。**

### 3.6 极点通道解析捷径(D7)
|z| < 1e-100 时 |z^p| > 1e223,再一步就溢出 double 范围(现行引擎的**潜伏 bug**,顺手修)。
解析化:z 极小 ⇒ z' = z^p(巨大,trap(z') 由解析式直接算,log 域),z'' = K + z'^p 其中 |z'^p| < 1e-490 ⇒
z'' = K(至 QD ulp 精确)。两步合成一个解析步,同时记两步的 trap 贡献。证书按解析式的条件数更新。

### 3.7 渲染管线(不变的部分)
`IExactZoomRenderer` 合约、每帧原生分辨率、非精确源抛异常、ffmpeg 管道、CLI(`--corruptionvideodeep`
等)、逐关键帧进度日志——全部保留。`VideoRenderer` 不感知精度阶梯,只拿最终位图。

## 4. GPU 决策(D5)

**选型:ILGPU**(NuGet 包,唯一新依赖)。理由:内核即 C#(单语言、单套数值代码),后端覆盖
CUDA/OpenCL/CPU;`Math.FusedMultiplyAdd` 映射到硬件 FMA(dd/ff 的 TwoProd 依赖它,必须验证生成的
PTX 确实是 fma 指令——写一个 microbench 断言 TwoProd(1+2^-30, 1+2^-30) 的误差项非零);
**CPU accelerator 跑同一份内核 = 测试 oracle**,不是第二套代码路径(忠于"不留 fallback")。
升级判据:若 dd 内核实测 < 35% 器件 FP64 FMA 峰值,才考虑 CUDA C 原生库。

内核结构:
- 每像素状态 ≈ 48–64 B(δ、scaleExp、n、refIdx、e、trapMin、flags);1080p ≈ 130 MB ✓。
- 按 64 迭代分块 + stream compaction(逃逸/出证书者退场),消除长尾发散。
- 轨道表(四档窄化)+ 最近点 LUT + BLA/段表:全部 < 1 MB,constant/L2 常驻 ⇒ 内核是纯 FMA 吞吐型。
- 档位即独立内核:rung0/1 内核吃 FP32 单元(消费卡的真正算力所在),rung2/3 吃 FP64 单元,互不抢占。
- 帧间无共享状态(除只读表)⇒ 多帧可流水线并行编码。

**为什么旧结论"GPU 不划算"不再成立**:旧架构 98.8% 时间在 CPU 端 BigInteger 修复轨道,GPU 无处发力;
新架构 repair 归零、像素循环占 ~95%,且大多数像素落在 FP32 档——正好是消费级 GPU 唯一充裕的资源。

## 6. 明确否决清单与不变量

**否决**(实施者不得复活):
- R1 任意精度逐像素上 GPU(内存/发散灾难;阶梯使其无必要)。
- R2 纯 FP32 无证书(无法认证 = 劣化)。
- R3 tile/局部修复轨道(本文档的前身方案,已被 D3 取代——它治症状,rebasing 治病因)。
- R4 跨像素插值/邻居播种/任何近似共享(解耦区间的像素在信息论上不可共享,耦合区间已由轨道共享覆盖)。
- R5 无证书的 BLA 跳步(会静默改变 trap-min/逃逸判定)。
- R6 继续深挖 BigDecimal 超越函数性能(D8;AP 已退出热路径)。

**不变量**:
- I1 循环边界:逐像素最多前进 `min(N−1, len−1)` 步(镜像 BStyleColoring;违者触发常数差指纹测试)。
- I2 一切数学常量取 double 二进制精确值,经 `FromDoubleExact` 单一来源分发。
- I3 参考轨道对负幂**不得提前终止**(逃逸后折返;截断即修复风暴——已实测)。
- I4 `IExactZoomRenderer` 合约与"非精确源抛异常"保留;LOD 相关 API 永不回归。
- I5 每个新数值类型(FF32/QD)接入前必须通过 vs BigDecimal 的 `--ddcheck` 式全套对拍。

交互式预览(降迭代数/降分辨率仍是精确渲染,不是近似)可达准实时。

**最优性(诚实版"宇宙最优")**:像素颜色对解耦步是混沌敏感的 ⇒ 每像素的解耦步必须以
≥0.204·(解耦步数) 位逐像素算,不可共享、不可跳过——这是信息论下界;耦合步可共享(单轨道)且可
跳过(BLA)。本架构对两类步都贴着下界走,剩余空间只有算术常数因子与硬件利用率。
在"逐帧精确、零近似"的约束下,**这就是最优解的形状**;更快只能改约束(即劣化,已被禁止)。
